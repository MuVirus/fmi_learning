# 分享会讲义

本目录存放面向**对外分享 / 内部培训**的演示材料。与 `docs/notes/`（课程正文，自学者用）分开：

| 目录 | 定位 | 受众 | 形态 |
| --- | --- | --- | --- |
| [`docs/notes/`](../notes/) | 课程正文，9 章，系统且详尽 | 自学者 / 教材 | Markdown 讲义 |
| [`docs/talks/`](#) | 分享会材料，单场次、限时 | 听众 | PPT + 讲稿 + 讲义 |

## 目录结构

```
docs/talks/
└─ <场次-slug>/              # 一场分享一个子目录
   ├─ outline.md             # 大纲（本场次的内容骨架，先定这个）
   ├─ slides/                # 幻灯片源文件（Markdown / Marp）
   ├─ handouts/              # 听众拿走的讲义
   └─ assets/                # 图片、截图、图表素材
```

## 写作约定

- **`outline.md` 先行**：任何 PPT 动手前，先在大纲里把「讲什么、讲多久、观众要带走什么」定下来。
- **每页标注时长**：合计必须等于总时长，留出 5% 缓冲给 Q&A。
- **事实必须可溯源**：所有 API 签名、状态机规则、能力标志语义都要指回 `docs/spec-3.0.2/` 的具体章节，或仓库里的可运行代码。
- **区分「规范要求」与「Reference 实现的做法」**：这两者冲突时以规范为准，PPT 里要标明。
- **演示脚本可复现**：demo 用到的命令要在仓库根目录能跑通。
- **每个技术点配一个「反面例子」**：软件工程师听众最吃「这么写会怎样炸」。

## 从大纲到 PPT 的流程

1. **定大纲**（本目录）——确认内容结构与时间分配。
2. **备素材**——把 `assets/` 里需要的截图、代码片段、运行输出准备好。
3. **写幻灯片**——推荐用 [Marp](https://marp.app/) 写 Markdown 再导出 PDF/PPTX（本机有 Node.js，`npx @marp-team/marp-cli` 可用）。
4. **写讲稿**——每页的 `<!-- notes -->` 里放口播内容。
5. **排练**——按大纲标注的时长跑一遍，超时砍内容。
